# mjt-shares

Static, encrypted shares generated by Memex.

This repository is a publication target, not a private store or authoring
workspace. GitHub Pages serves a small browser reader and immutable encrypted
objects. The bearer key belongs only in the URL fragment and must never be
committed here.

## Current status

Experimental proving ground. The local encoder and browser reader are working,
including project-site prefix mapping. Automated publication and
recipient-device verification are not yet enabled. Treat both the repository
and its Pages output as public.

## Initial Pages configuration

Use GitHub Pages **Deploy from a branch** with:

- branch: `master`
- folder: `/(root)`

This repository exists only for the static published tree, so a second
`gh-pages` branch would duplicate state without buying useful isolation. The
published branch is the inspectable source of truth. If this repository later
gains source code or a build pipeline, reconsider that choice rather than
quietly mixing source and generated output.

GitHub still documents both `/(root)` and `/docs` as branch-source folders. Root
is intentionally simpler here; `/docs` is not required.

The expected project-site base is:

```text
https://matthewjosephtaylor.github.io/mjt-shares/
```

That `/mjt-shares/` prefix is an HTTP deployment detail, not part of an encrypted
object's canonical identity. The browser transport must map canonical
`/share-data/v1/...` paths beneath the project-site base. That mapping is
implemented and covered by the reader's transport tests; its first proof through
the real Pages URL is still pending.

## Published layout

```text
.nojekyll

share/v1/
  index.html                         versioned reader shell

share-data/v1/
  <shard>/<storage-index>/
    manifest.bin                    encrypted root manifest
    objects/...                     immutable encrypted objects
```

The reader code and encrypted objects are released independently. Compatible
reader fixes stay under `share/v1/`; an incompatible protocol requires a new
versioned path.

`share/v1/index.html` is generated from the Think workspace reader at commit
`d8a565a3`; do not hand-edit it.

## Security and retention

- Anyone with the complete fragment-bearing URL can decrypt that share.
- URL fragments are not sent in HTTP requests, but they can remain in browser
  history, bookmarks, screenshots, messages, and recipient copies.
- Git commits contain ciphertext and nonsecret routing data only—never
  plaintext drafts, bearer keys, full secret URLs, credentials, or tokens.
- Removing a live file is not revocation. Git history, caches, forks, clones,
  and recipient copies may retain the ciphertext indefinitely.
- Reader pages must load no analytics, advertisements, or third-party runtime
  resources.

## Publication rules

1. Stage and fully verify each publication outside this repository.
2. Add only its immutable ciphertext paths in one focused commit.
3. Never overwrite an existing publication path or force-push `master`.
4. Preserve unrelated repository work.
5. Do not return a share URL until the exact Pages deployment and real HTTPS
   reader path have been verified.

Until the publisher is implemented, all repository and Pages changes remain
manual and deliberate.
